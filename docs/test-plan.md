## Test Framework
Vitest (TypeScript native, CF Workers compatible)

## Unit Tests (src/shared/)

### crypto.ts
- Key generation produces valid X25519 keypairs
- DH shared secret derivation: same result from both sides
- Encrypt/decrypt round-trip: plaintext matches
- Encrypt with empty plaintext
- Max message size enforcement (256KB)
- Decrypt with wrong key fails gracefully
- Decrypt with tampered ciphertext fails
- Decrypt with truncated ciphertext fails
- Nonce uniqueness: two encryptions of same plaintext produce different ciphertexts

### protocol.ts
- Serialize/deserialize round-trip for each message type (task, context, result, chat)
- Protocol version mismatch detection
- Invalid JSON handling
- Missing required fields handling
- Max size validation before serialization

## Unit Tests (src/daemon/)

### tasks.ts
- Task lifecycle: pending → ack → in_progress → done
- Task lifecycle: pending → failed (no ack timeout)
- Timeout enforcement: 60s no-ack → failed
- Timeout enforcement: 5min no-result → failed
- Message deduplication by ID (bounded to 1000)

### watcher.ts
- Incoming task triggers claude-code spawn
- Claude Code not installed: graceful error

## Integration Tests

### Two bridge instances via wrangler dev
- Room creation and joining via room code
- Key exchange completes successfully
- Encrypted message send/receive round-trip
- Sync replay after reconnection
- Invalid/expired room code rejection
- Peer offline → message queues → reconnect → delivered

### MCP tools via daemon HTTP API
- bridge_send_message: sends via daemon
- bridge_get_messages: reads from daemon queue
- bridge_send_task + bridge_get_tasks: task lifecycle

## E2E Tests (manual checklist)

### Room pairing flow
- [ ] Host creates room on machine A, gets room code
- [ ] Joiner enters code on machine B, key exchange completes
- [ ] First encrypted message sent and received

### Task dispatch flow
- [ ] Server sends task → local daemon receives → Claude Code session spawned
- [ ] Claude Code completes task → result sent back → server sees 'done' status

### Security verification
- [ ] Intercept WebSocket traffic with proxy → all payloads are opaque encrypted data
- [ ] Room metadata only contains: room code, public keys, timestamps, status

## Critical Paths
- Room pairing + key exchange must complete before any data messages can be sent
- Task dispatch → watcher → Claude Code spawn is the core value proposition
- Encryption round-trip correctness is security-critical
